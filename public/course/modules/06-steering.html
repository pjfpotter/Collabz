Lanes, shared helpers, and the rule to not cross

🛣️

Your own slice

Each person owns specific routes. Change only those.

🤝

Shared helpers

Reach another track only through getCurrentUser, scoreUser, openConversation and friends. Never their internals.

🚧

Flag schema changes

Every track builds on the same tables, so a change to schema.prisma is raised with the group first.

🎭

Pretend cohort

32 pretend students on the dev database, so nobody waits for another track.

This is also how two AI agents working at once avoid conflicts: each stays in its lane, and the shared helper keeps its name and return value even when its inside changes.

Reading a symptom

The API route answers with a number. The number tells you which layer to inspect. This is the real table from src/app/api/messages/[conversationId]/route.ts.

CODE 
const STATUS_FOR_REFUSAL: Record<SendRefusalReason, number> = {
  "not-found": 404,
  closed: 409,
  "not-connected": 409,
  empty: 422,
  "too-long": 422,
};
PLAIN ENGLISH

A lookup table: for each reason the helper can give, which number to send back.

Not yours or does not exist: 404.

Closed, or the two are no longer connected: 409, a conflict with the current state.

Empty or too long: 422, the words themselves are not acceptable.

"It's not showing up": where to look

1
Is it a page or an action? Check the status number

401 means not signed in, 404 not yours or missing, 409 state conflict, 422 bad input.

2
Is the person even visible?

Unfinished profiles and suspended people vanish from the graph, search and scores by design.

3
Did a pairing or tag change without a rescore?

Pairing edits change no score until "Rescore everyone" is pressed.

4
Which database are you on?

Laptops, previews and tests use the dev branch. Only the live site uses production.
